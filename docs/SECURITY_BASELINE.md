# Security Baseline (MVP-9)

## Current Controls

- `.env` files are gitignored.
- `.env.example` defines non-secret local contract.
- Backend errors are normalized; unexpected exceptions do not leak stack traces by default API contract.
- Request IDs are generated per request and returned in headers/payload for traceability.
- Session tokens are required for project, conversation, run, usage, and audit endpoints.
- Project ownership is enforced: users can only list, read, or mutate their own projects and related conversations/runs.
- Idempotency keys are scoped to the authenticated user so one user cannot replay another user's mutation result.
- In-memory rate limiting (100 requests/minute/IP by default) is applied to non-health routes.
- JSON request bodies are limited to 1MB.
- Structured logs and audit `parametersMetadata` redact password, token, API key, and related secret fields.
- Approval-required Blender transforms remain gated behind preview/apply/undo operators.

## Non-Controls (Deferred)

- Persistent user store, salted password hashing, token expiry/revocation, and SSO
- provider credential vaulting and BYOK
- durable audit log storage (current logs are in-memory)
- billed usage and cost controls
- enterprise policy engines

## Baseline Rules

- Do not run arbitrary Python generated by an LLM.
- Do not run shell commands from model output.
- Treat `.blend` and project files as untrusted.
- Do not expose secrets in logs.
- Do not return another user's project as `403`; use `404` to avoid leaking existence.
